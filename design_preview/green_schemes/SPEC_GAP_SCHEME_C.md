# 方案 C「新芽晨光」规格差异对照与调整清单

> 比对基准：`design_preview/green_schemes/scheme_c_sprout.html`（方案 C 源稿，作为**规格书**）
> 比对对象：当前应用实现（`lib/`，2026-09-19 配色换代后状态）
> 结论一句话：**色彩体系已对齐，但几何形态、组件构成与信息层级几乎没有一项落地** —— 上一轮只换了色，方案 C 的「形」没进来。

---

## 0. 为什么上一轮看起来「不像方案 C」

上一轮的改动收敛为「把 `AppColors` 里 26 个色值换掉 + 四处镜像同步」。这解决了**颜色**问题，
但方案 C 的辨识度**主要不在颜色**，而在三处更硬的东西：

1. **一张当前完全不存在的卡** —— 今日概览 Hero（浅绿底 + 分段进度条 + 64px 环形）。
   它是方案 C 手机 2 的视觉锚点，占屏幕上部约 1/4，缺失后整页「没有主角」。
2. **卡片的组织方式相反** —— 方案 C 是「一项一张独立白卡」；当前是「一张大面板里塞多行 + 每行左侧
   3px 状态色竖条」。后者正是方案 C 通篇没有使用的样式语言。
3. **元信息的表现方式相反** —— 方案 C 用 `pill` 标签承载状态/项目/时长；当前用一行拼接文本
   `待处理 · 一次性任务 · 计划 2026-08-07 09:00 · 截止 …`。

因此本次调整的对象是**几何、组件形态与信息层级**，色板不再改动。

这说明标尺本身没问题，问题在**页面没有按标尺去搭组件**。

## 3. 组件级差异

| | 方案 C | 当前实现 |

### 3.8 一处**有意偏离**（需明确记录）

方案 C 的 Hero 卡用了 `linear-gradient(125deg, sprout-050, sprout-100)`，画布背景用了两层
`radial-gradient`。项目现行规范**明文禁止装饰渐变**（`ORGANIC_UI_SPEC.md`，面板一律实色 + 1px 中性边框）。

处置：**Hero 卡改用实色 `sprout-050` 底 + 1px `sprout-200` 边框**。
保留「浅绿托底、与白色卡片区分」的视觉意图，不引入渐变。画布渐变异同样不带入。
