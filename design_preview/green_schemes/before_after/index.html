有意保留的差异6 处 · 逐条有理由，勿「顺手改回」

#元素偏离理由
A概览卡底色渐变 → 实色源稿用 linear-gradient；现行规范明文禁止装饰渐变与玻璃拟态。改用实色 + 1px 边框，保留「浅绿托底、与白卡区分」的意图。
B桌面展开指示保留 ⌄方案 C 只描述手机。桌面卡宽约为手机 1.8 倍，去掉后右侧大片空白且丢失「可展开」线索。**仅 width ≥ 768 出现。**
C页头搜索图标保留ui_coverage_regression_test 守卫「移动端今日可达全局搜索」，属功能要求，不能为对齐效果图而删。
D捕获页文案新增 / 收下源稿是「随手记 / 保存到收件箱」。保留产品内既有文案体系。
E承诺卡动作名专注此项「开始专注」是「下一步行动」面板的主按钮文案。同名会让「今日只暴露一个行动」的守卫失效——测试已实测拦下。
F今日重点右侧状态 + 调整重点源稿此处是「全部 →」。实际承载的是当日流程状态与「调整重点」入口（有测试守卫），语义不同故保留。

两条易被误判的观察：
① golden 里 FAB 外面那圈黑边不是缺陷——flutter_tester 不支持阴影模糊，把 drawShadow 画成了实心剪影。改造前的基线同样存在 167 个纯黑像素，真机是柔和投影。不要为「修」它改产品代码。
② 源稿里「今日重点」标着「剩 3 项」而 Hero 说「还剩 5 件事」——说明该分区本就是全量任务的**子集**。据此，「今日」与「今日重点」是**有意保留的双层结构**，两层共用同一种卡；移动端把重复部分从「今日」剔除，全为承诺时整段省略，页面顺序即与源稿一致。

要害二 · 概览卡：桌面同样置顶

改后新增12 段进度条 + 64px 环形 —— 与移动端是同一个组件

它是方案 C 的视觉锚点。缺了它，同一天在两个端上是两种观感——而它本来就不是「移动端专属组件」。 桌面保留两栏架构（右栏 380px：今日重点 + 成长进度）是 §8.1 的明文规定，方案 C 只画了单列手机， 并不构成对两栏的否证；把桌面拍扁成单列是过度适配，不是「保持一致」。
