# 个人工作台双主题全界面升级执行方案

> 决策：**柔壤图鉴**为白天／浅色主题，**夜航工作室**为夜间／深色主题。适用 Windows 桌面与 Android 手机、平板。本文是后续 Flutter 实现与验收的执行依据；九张主题例图只用于确定视觉方向，不充当产品页面或真实数据。

## 0. 完成范围与约束

- 覆盖 `WorkbenchSection` 可到达的全部页面、子页，以及专注会话、编辑器、搜索、快速收集、弹窗、底部弹层、空白／加载／错误／校验状态。每个实际页面都要有**符合自身任务的特色视觉组件和功能性信息层级**，Windows 和 Android 分别设计，不能只装饰今日与项目页，也不能把同一张插画和同一种统计卡复制到所有页面。
- 保留本地 SQLite、可选 Supabase 同步、已有记录模型、控制器调用、导航目标、任务结算、焦点计时、日周月回顾、CTDP／RSIP、自律保护与导入导出逻辑。例图中的任务与进度是演示数据；Flutter 界面一律读取真实状态，不写死例图数字。
- 保留现有 `theme_mode = system | light | dark` 元数据和值，不做数据库迁移。`light` 映射柔壤，`dark` 映射夜航，`system` 跟随操作系统亮度。系统模式不是按钟点自行换肤。
- Android 不呈现无法在本机执行的 Windows 进程结束、hosts 修改等操作。限制规则的可查看／可编辑内容按现有能力展示；平台说明应准确，不画出不可用的“假按钮”。
- 旧版 `ORGANIC_UI_SPEC.md` 中“所有有机形态必须编码数据、禁止装饰插画”的条款需修订：新方案允许少量**与当前任务语境相关的无文字插画**，仅放在首页引导、领域入口或空状态；所有状态和进度图形仍必须映射真实数据。插画不遮挡文案、按钮或输入区。

## 1. 两套统一而有区别的视觉语言

保留并重新校核“危险／错误”“信息”“目标／习惯”“RSIP 八类节点”的独立语义色。夜航的琥珀色只代表成果和里程碑，错误继续使用独立的红色；同一状态不能仅凭颜色区分，还需图标、形状、标签。禁止在夜航主题中给每张卡都叠霓虹泛光；高密度阅读区域使用稳固的深色工作面。

### 1.2 字体、空间、形状与图标

- **字体**：沿用已内置、有许可证的字体。柔壤的页面主标题／短标语用 LXGW WenKai GB Medium；夜航标题改用 IBM Plex Sans SC Semibold；两套的正文、表单、列表用 IBM Plex Sans SC；计时、时间尺、编号和统计值用 IBM Plex Mono。中文正文以 15–16sp、约 1.5–1.65 行高为主；手机主标题约 24sp，桌面约 28sp；正文可放大到 200% 时不断字、不截断主要操作。
- **间距与宽度**：沿用 `AppSpacing` 的 4／8／12／16／24／32／56 级。内容边距约 20–24dp；整个工作区最大 1600dp，今日两栏整组最大 1520dp、列间距固定 24dp，主栏随剩余空间扩展。单列工作表面最大 1120dp；长文阅读列单独限制为 760dp。标题、工具条与对应内容共用宽度边界，禁止把各列独立居中而产生巨大的内部空隙。数值统一于 `AppLayout`。
- **圆角**：主题级形状令牌：柔壤主面板 20、内卡 16、控件 12；夜航主面板 18、内卡 14、控件 12；弹窗 24、底部弹层顶部 28。主题切换时只改变外观，不改变控件高度和布局测量。
- **层次**：柔壤使用轻纸面、细描边和低强度扩散阴影；夜航用深浅面、细描边和局部内光，尽量少用实际模糊与大面积透明叠层。背景纹理只占弱对比度、不出现于正文背后。
- **图标**：优先用项目已有 Flutter 图标和原生 SVG／自绘矢量；20／24dp 两档为主，笔画、光学中心一致。功能图标必须有文字标签或 Tooltip／Semantics。植物线、时间轨道、节点连接等页级母题用 `CustomPainter`／SVG，支持缩放且不增加位图体积。
- **动效**：按压／悬停约 120ms，展开／弹层约 180ms，页面过渡不超过 220ms；完成反馈只短暂出现一次。计时器数字稳定更新，不让整张卡跳动。尊重系统减少动态效果，此时去掉视差、交错和非必要过渡。

### 1.3 主题切换体验

“设置 → 外观”呈现两张**原生控件构成的迷你主题卡**，说明“白天 · 柔壤图鉴”“夜间 · 夜航工作室”和“跟随系统”。点选立即预览并异步持久化，重启后保持；写入失败要恢复上次选择并提示重试。系统模式实时响应系统亮度。切换后同步系统状态栏、Android 导航栏、弹窗、菜单、SnackBar、Tooltip 与输入法相关表面，正在编辑的内容和滚动位置保持。沿用既有键 `theme_mode`，仅调整设置文案、视觉预览和反馈。

## 2. 双端布局规则

| 宽高 | 导航与内容 | 交互安排 |
| --- | --- | --- |
| `<768dp`，或 Android 高度 `<600dp` | 手机布局：4 项底栏＋“更多”抽屉，单列内容；页级特色图形缩为横向条带、小插图或信息图。Windows 低高度窗口仍保留侧栏，以滚动承载内容。 | 主要操作靠近拇指区；底栏、FAB、键盘和安全区不遮挡最后一项。次级操作进更多菜单／底部弹层。 |
| `768–1199dp` | 收起宽侧栏或导航轨；双栏只在真实空间够用时出现。 | 项目与笔记可主从切换；表单不强行并排。 |
| `≥1200dp` | 展开侧栏；今日、项目、计划等采用主列＋辅助栏，辅助栏只显示当前页面有用的信息。 | 可见快捷操作、悬停状态、键盘焦点；不让阅读列被拉成整屏。 |

基准视口为 Windows `1440×900`、`1024×864`，Android `390×844`，补测 `320×568`、`700×420`、`800×450`、`768×864`、`1200×864`、`1440×500`、`1536×864`、`1876×979`、`1920×1080`、`2560×1440`。页面断点依据扣除导航后的实际空间；200% 字体下提前改单列。Android 平板按空间适配，但触控目标仍按触控标准。周时间轴、项目看板与习惯日期矩阵允许局部横向滚动，并提供可见线索；国策树在限定高度内自动适配画布，保留平移、缩放和“适应窗口”操作。

低高度紧凑横屏将快速新增移入页头，避免悬浮按钮遮挡进度；普通竖屏保留悬浮入口。专注模式在窄屏及大字号时使用下拉选择，空间足够时使用分段按钮，缩放窗口不重置已选模式。具体实现与证据见[自适应布局验收](RESPONSIVE_LAYOUT_VALIDATION.md)。

## 3. 逐页设计清单：每页有自己的信息图形与操作重心

共同原则：每一行的特色元素在柔壤和夜航都存在，换肤只改变材质、色彩和同主题插画，不改变信息含义。表中“元素”都从当前控制器的实际数据计算；没有数据时显示相应空态，不伪造进度。

### 3.1 今日、计划与项目

| 项目任务 `projectsTasks` | 任务清单／看板均展示状态计数、进度与真实层级；看板列宽和空列说明固定，不以图像填充空列。 | 清单为默认，分段控件切换看板；看板按列分页或局部横滑并提示列数；新增任务继承当前项目。 |
| 项目任务群 `projectsGroups` | 关联任务群的结构图、顺序／并行说明、成员状态与编辑入口。 | 群卡纵向展开成员关系；锁定原因可点开查看，创建按钮位于内容流而非远离拇指的顶角。 |

| 项目笔记及回顾 `projectsNotes` | 关联笔记采用文档索引样式，回顾区展示期间与最近更新；点击保持现有编辑／跳转行为。 | 笔记与回顾分段列表，摘要最多两三行，进入后有明确返回项目路径。 |

### 3.4 所有页面共用但必须完整设计的交互面

- **导航与搜索**：侧栏树、手机底栏、“更多”抽屉、全局搜索、面包屑／返回路径、未保存状态都遵循同一主题。当前页有清楚选中态；手机次级页仍知道自己属于“计划／记录／成长”的哪个域。
- **快速收集与编辑器**：`quick_capture_sheet.dart`、`record_editor_dialog.dart`、`markdown_editor_dialog.dart`、`task_group_editor_dialog.dart`、`relation_picker_dialog.dart`、`attachment_panel.dart` 的输入、预览、关联、上传、校验、保存中、保存失败、放弃修改均落地。Windows 对话框最大宽度受限；Android 底部弹层随键盘与安全区调整，主按钮不被遮挡。
- **任务行与批量操作**：`task_row.dart`、`task_hierarchy.dart`、`batch_task_toolbar.dart` 覆盖默认、悬停、聚焦、按压、选中、完成、失败、跳过、逾期、锁定和加载反馈；状态始终有文字。多选不会改变已有任务数据流。
- **通用组件**：`solid_panel.dart`、`common.dart` 的页面标题、分区标题、状态标签、空态、进度、提示条和表单字段建立统一尺寸；一页最多一个主要填充按钮区域，次级操作用描边／文字按钮。Toast／SnackBar 有成功、信息、警告、错误及可撤销路径。
- **空态／加载／错误**：每个领域空态写明“现在是什么状态”和一个真实可执行动作，允许小尺寸领域插画；加载时只显示实际异步区域的占位骨架，避免全屏闪烁；失败时保留用户输入、说明原因并给重试／返回路径。所有图像均不承载唯一信息。

### 3.5 可直接实现的组件与状态规格

| 组件 | 尺寸、排版与交互 | 完整状态 |
| --- | --- | --- |

| 卡片与任务行 | 卡片有清楚的整卡可点范围或独立操作按钮，二者不重叠；层级靠标题、辅助行、状态及间距表达。时间和数字用等宽字体。 | 选中、展开、逾期、锁定、完成、更正、批量选择；右键与长按均有可见按钮替代。 |

## 4. 素材交付与性能

1. 将已完成的四张无文字插画从 `design_preview/theme_concepts/assets/{green,night}/{today,project}.png` 归入 `assets/illustrations/{day,night}/`，并在 `pubspec.yaml` 注册。例图中的中文、数字、按钮不裁切进插画，继续用 Flutter 原生文本和控件渲染。
2. 补充同一风格的五组双主题插画：**快速收集、专注准备、知识笔记、周期回顾、成长证据**。每组只放在对应领域入口或空态；密集的周历、关系树、自律规则、分析图改用可缩放的原生 SVG／`CustomPainter`，直接由真实数据生成。所有新增素材都需是最终成品，不使用临时占位图。
3. 给每张图明确安全裁切区、横幅／窄屏构图、透明背景策略；导出合适的分辨率版本并压缩，优先测试 WebP，必要时用优化 PNG。目标是生产插画合计不超过约 5 MB、移动端单张解码尺寸只略高于显示需求；以真机清晰度和解码结果为准，不为了数字牺牲画质。
4. 集中在主题资源映射中选择 day/night 版本；页面按需加载、提供稳定宽高、`cacheWidth` 或分辨率变体，避免主题切换和滚动时跳动。无文字插画设 `ExcludeSemantics`，重要信息用旁边的文本复述。
5. 已有品牌 SVG 和字体继续使用并保留许可证。未选中的“日光编辑室”素材留在设计预览，不打入应用包。产出素材清单包含来源、主题、页面用途、尺寸、压缩后体积及移动裁切验收图。

## 6. 验收矩阵与完成定义

### 自动检查

```powershell
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test --reporter compact
python tool/verify_colors.py
python tool/verify_token_parity.py
```

扩展 `test/theme_accessibility_test.dart`、`test/common_visual_system_test.dart`、`test/ui_audit_screenshot_test.dart`、`test/visual_golden_test.dart`：所有真实路由／子页分别用**两主题**在 `390×844`、`1024×864`、`1440×900` 跑无溢出快照；重点补 `320×700`、`768×864`、`1200×864`、`1536×864`、200% 字体和减少动态效果。Goldens 先人工比较，再更新基准，不以批量覆盖掩盖问题。

### 手工真机与交互

- Windows 运行、检查侧栏、拖拽周计划、项目看板、笔记长文、专注后台恢复、规则编辑与主题切换；Android 运行、检查分享快速收集、单手新增、底栏与“更多”、日期和项目选择、回顾编辑、键盘弹层、返回和夜间系统栏。设备不可用时明确记录未完成项，不以模拟图替代真机结论。
- 每个页面核对：两个主题、内容充足／空／加载／错误、当前选中／悬停／按压／键盘聚焦、长标题、真实数据变化。普通文本对比度至少 4.5:1，大文字和关键信息图形至少 3:1；Android 触控目标至少 48dp；图表有数值／标签；颜色不作为唯一编码。
- 检查全屏宽度与低高度窗口无 RenderFlex overflow、横向意外滚动、被底栏／FAB／键盘遮挡；插画在横竖屏不裁掉主体；主题切换时滚动和输入内容不丢。验收可回溯到各页面截图、测试记录和第 3 节清单。

### 完成条件

1. 第 3 节每一行至少交付一个**该页面独有、与业务相关**的可见图形／组件，以及一条清楚的主操作；两主题、Windows 和 Android 可达视图均已审图。不能用“已套用全局颜色”代替逐页完成。

3. 最终插画已打包、清晰、无占位、无文字烘焙；运行与自动检查通过；更新后的文档、截图、资产清单和剩余限制一并交付。
