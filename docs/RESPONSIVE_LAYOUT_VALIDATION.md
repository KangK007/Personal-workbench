# 全页面自适应布局修正与验收

日期：2026-10-09。延续[双主题升级](DUAL_THEME_VALIDATION.md)，针对窗口缩放、超宽窗口、低高度窗口和大字号进行修正。柔壤图鉴与夜航工作室共用布局逻辑。

## 1. 已修正的问题

| 范围 | 原因与修正 |
| --- | --- |
| 今日宽屏 | 主列单独居中且限制为 720dp，和辅助列之间产生大面积空白。现在对两列整体限宽，主列占剩余空间，列间距恒定 24dp，辅助列按空间取 280–360dp。 |
| 全页面断点 | 原来部分页面按整个窗口宽度判断，未扣除侧栏。增加 `WorkbenchViewport`，页面按实际可用空间切换单列、主从和时间表。弹窗仍读取完整窗口与键盘空间。 |
| 内容扩展 | 统一工作区、表单、阅读和今日的宽度上限；超宽窗口整体居中，避免列间留白失衡，也避免长文拉满整个屏幕。 |
| 标题与内容 | 页头、收集箱、设置、专注准备、回顾和笔记使用对应内容框架；统一桌面水平边距，笔记索引与阅读页整体居中。 |
| 低高度窗口 | Windows 宽而矮的窗口保留侧栏并滚动内容；Android 横屏采用紧凑导航，隐藏重复页头。低高度横屏把快速新增移入顶部工具栏，避免悬浮按钮盖住进度内容；竖屏保留原有悬浮入口。 |
| 导航展开动画 | 侧栏从 80dp 展开时，完整标签曾在尚未展开的宽度内排版，产生瞬时溢出。内部按目标宽度布局，外层裁切并动画展开。 |
| 项目与笔记 | 主从结构按实际空间及字体比例判断；空间不足自动改单列。笔记正文单独限制阅读宽度，索引保持 280–320dp。 |
| 周时间表 | 五日并排按真实内容宽度与字体比例判断；日期头由固定高度改为最小高度，支持大字号换行。 |
| 国策树 | 修正条件分支绑定导致桌面图形缺失的问题；画布首次进入和缩放窗口后自动适配，保留平移、缩放和“适应窗口”操作。 |
| 空状态 | 空状态在短窗口和大字号下可滚动，说明及主操作不被裁掉。 |
| Markdown 编辑 | 表单在低高度和 200% 字体下独立滚动，正文保持可编辑高度，“保存／取消”保留在弹窗操作区。调整窗口后标题和正文仍可保存。 |
| 专注模式 | 视觉复核发现 320dp 的四段按钮把标签挤成竖排。窄屏／大字号改用原生下拉，空间足够时仍用分段按钮；两种形态共享当前选择，计时进行中均禁止修改模式。 |
| 页面状态 | 页面栈使用稳定的全局键，跨桌面／手机布局切换时保持页面 State 和未保存草稿；今日滚动位置与各折叠区使用独立存储键，避免类型冲突。 |

修改集中在 `lib/core/theme/app_theme.dart`、`lib/ui/widgets/workbench_layout.dart`、公共组件、应用壳和各页面的容器判断。保留路由、记录模型、持久化字段和业务调用。

## 2. 落地的布局规则

所有数值为 Flutter 逻辑像素（dp）。

| 令牌或条件 | 值与用途 |
| --- | --- |
| `AppLayout.workspaceMax` | 1600，整体工作区上限 |
| `AppLayout.todayMax` | 1520，今日主列与辅助列整体上限 |
| `AppLayout.formMax` | 1120，表单、设置和收集等内容上限 |
| `AppLayout.readingMax` | 760，笔记正文阅读上限 |
| `AppLayout.columnGap` | 24，今日两列间距 |
| `AppLayout.todaySplitMin` | 实际内容宽度 940 起，随字体比例上调至最多 1.6 倍 |
| `AppLayout.masterDetailMin` | 实际内容宽度 880 起，随字体比例上调至最多 1.5 倍 |
| 外壳紧凑布局 | 窗口宽度小于 768；Android 还在高度小于 600 时采用紧凑布局 |
| 外壳展开侧栏 | 窗口宽度 1200 起 |
| 国策图形 | 容器高度 280–640；首次适配比例 0.25–1，用户缩放范围 0.25–2.5 |

超过内容上限的余量留在整个内容组两侧，组内不再额外插入巨大空白。局部时间表、矩阵和关系画布保留必要的滚动或缩放。

### 布局矩阵

- 既有矩阵：1050 次检查，包含双主题的 320×700 至 1536×864、有内容、空状态、200% 字体和减少动态效果。
- 实际内容空间矩阵：35 视图 × 2 主题 × 11 场景 = **770 次**。9 个窗口尺寸为 320×568、700×420、800×450、1024×600、1200×700、1440×500、1876×979、1920×1080、2560×1440；另测 1024×600 和 1876×979 的 200% 字体。模拟扣除 Windows 侧栏或紧凑导航占用后再渲染页面。
- 短窗口空状态矩阵：35 视图 × 2 主题 × 3 尺寸 = **210 次**，320×568、800×450、1440×500，均为 200% 字体。
- 合计 **2030 次页面布局检查**。这不是 2030 个独立测试，也不等同于所有数据组合的人工像素验收。
- 共享弹窗：6 类编辑／搜索／收集面 × 7 尺寸与字体场景；检查打开、键盘焦点和关闭。
- 专项交互：今日列宽与 24dp 间距、导航展开、跨断点保留回顾草稿、笔记编辑器缩放后保存完整正文、国策树节点与适配按钮；既有悬停、按压、菜单、筛选和业务回归继续运行。

### Android 实际运行

最终源码的 debug APK 已构建、安装，并通过 `flutter run -d emulator-5554 --debug --no-pub` 启动。随后关闭调试连接、重启模拟器，以普通 Activity 启动再次确认。

- [竖屏 1080×2400](images/responsive-layout/android-portrait.png)：检查今日标题、插画、进度、主操作、可滚动任务区域、悬浮新增及底部导航。
- [横屏 2400×1080](images/responsive-layout/android-landscape.png)：检查紧凑导航、无重复页头、工具栏快速新增，以及不被悬浮按钮遮挡的进度圆环。
- 模拟器密度 420；截图尺寸为物理像素，布局按逻辑像素计算。临时窗口尺寸覆盖已恢复，最终 `wm size` 为 1080×2400，无 override。
- 复核过程中模拟器退出后留下了 0 字节的提取缓存：`kernel_blob.bin` 与 `isolate_snapshot_data`，而 APK 中对应文件完整。重新安装后提取缓存恢复为约 89MB／11MB，应用正常启动；[恢复后的资源长度](qa/responsive-layout-2026-10-09/android-cache-recovered.log)。没有清空业务数据库。
- 模拟器冷启动还出现过系统自身的 “System UI isn't responding” 弹窗；选择等待后恢复。最终两张截图均已复核为正常应用画面。此过程不作为真机性能证据。

## 6. 验证边界

- Android 实际运行使用本机模拟器；本轮没有 Android 物理设备，不据此宣称完成真机性能或厂商后台兼容性验收。
- 35 视图的全尺寸覆盖来自 Flutter 测试渲染；Windows 原生运行检查重点是窗口缩放和今日布局。未逐一通过原生鼠标操作全部页面。
- 自动矩阵检查渲染异常和语义结构，视觉总览检查代表性首屏；业务交互由现有及新增回归测试验证，不代表穷尽所有用户记录组合。
- 本轮不修改真实账号同步配置、自律保护动作或用户业务记录。
