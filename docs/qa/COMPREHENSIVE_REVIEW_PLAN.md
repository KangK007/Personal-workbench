# 个人工作台系统性代码与 UI 审查方案

> 目标：按当前源码逐模块、逐入口和逐状态验证 Windows 与 Android 的主要用户流程，主动寻找缺陷；本文件定义审查方法，不代表本轮已经执行了测试或确认项目无缺陷。
>
> 项目基线：Flutter / Dart，Windows + Android；应用入口为 `lib/main.dart`，应用组装在 `lib/app.dart`，导航由 `WorkbenchShell` 和 `WorkbenchSection` 实现（不是独立的路由框架），业务状态由 `WorkbenchController`、两个领域 mixin 和 `ChangeNotifier` 驱动。

## 1. 审查目标与原则

1. 从真实用户入口追踪到界面、控制器、服务、数据库或平台桥，再验证返回界面后的状态与持久化结果。
2. 以空数据、正常数据、边界数据、权限受限、离线和依赖失败等场景主动寻找错误；没有覆盖证据的功能不得标为通过。
3. 自动化测试、Windows/Android 真机或桌面测试、人工视觉检查分开记录。代码阅读、历史报告和单张 Golden 均不能单独证明端到端通过。
4. 测试使用临时数据库、可重复的时钟和隔离账号；备份恢复、删除、hosts 修改、强制结束进程等操作不得对用户真实数据或主机环境造成副作用。
5. 本轮开始时记录 Git 状态和工具链；不覆盖现有未提交改动。不得通过跳过测试、放宽断言或更新 Golden 来掩盖差异。

## 2. 审查范围

### 2.1 平台与应用外壳

| 范围 | 必查入口与场景 |
| --- | --- |
| 启动与初始化 | 冷启动、空数据库、已有数据库、迁移、加载、初始化失败、重试、关闭/重开、初始化服务失败 |
| 桌面导航 | `WorkbenchShell` 侧栏展开/折叠、分组展开、短窗口滚动、全部当前导航目标、兼容旧目标、页面切换时数据和滚动状态 |
| Android 导航 | 五项底栏、更多 Sheet、各页面可达性、上次子页记忆、系统 Back、弹层 Back/手势关闭、旋转和应用恢复 |
| 窗口与输入 | 窄屏、断点临界尺寸、低高度横屏、键盘焦点、系统快捷键、输入法遮挡、窗口尺寸实时变化 |
| 全局入口 | Ctrl+K 搜索、Windows Ctrl+Shift+Space 快速捕获、FAB、Android 分享入口、通知入口及权限拒绝降级 |

断点按代码和现行设计规范核对：`<768dp` 移动布局、`768–1199dp` 紧凑布局、`>=1200dp` 展开布局；另验证 `compactHeight` 低高度分支，以及宽高处在断点两侧时的导航切换。

| 回顾 `review_page.dart` | 日/周/月切换、事实快照、编辑/保存/取消、版本、历史只读、未来周期限制、旧 diary 兼容迁移 |

### 2.3 共享组件与交互表面

逐个清点 `lib/ui/widgets/` 中可交互组件及各页面私有 Dialog/Sheet：任务行/层级、批量工具条、通用记录编辑器、任务群编辑器、关联选择器、快速捕获、全局搜索、Markdown 编辑器、附件面板、移动底栏、菜单/下拉、确认框、空态、加载态、Snackbar/错误提示。每个操作控件均检查默认、悬停（桌面）、按下、焦点、选中、禁用、加载、成功和失败状态；破坏性操作另测确认、取消及撤销/恢复路径。

### 2.4 状态与依赖链

| 层 | 检查内容 |
| --- | --- |
| Shell/路由 | `WorkbenchSection` 当前枚举、`_buildPage`、旧别名归一、桌面/移动导航映射、返回历史、页面子状态记忆 |
| 状态管理 | `WorkbenchControllerBase`、主 Controller、Restriction/RSIP mixin；派生状态、通知时机、重复/并发操作、失败回滚、监听器和 Timer 释放 |
| 数据 | SQLite schema/升级迁移、事务、唯一性、软删除、关系完整性、重启持久化；附件元数据与文件的一致性 |
| 服务 | 搜索、备份、附件、专注、通知、成长、SelfControl 导入、自律策略/安全/监控、分享、Supabase 同步 |
| 平台边界 | Android 通知/精确闹钟/分享/IME/Back；Windows 托盘/快捷键/进程监控/hosts/UAC/启动项；不支持能力须有明确降级反馈 |

核心依赖路径按“页面 → Controller → Service → SQLite/文件/网络/MethodChannel → 状态通知 → 页面反馈”追踪。关键链路至少检查成功、业务拒绝、超时/异常、重试和重复提交。

## 3. 审查维度、方法与判定标准

| 维度 | 检查方法与路径 | 通过标准 |
| --- | --- | --- |
| 功能正确性 | 对每页建立动作清单；用真实导航完成新增→编辑→查询→完成/归档→恢复/删除，并在重启后复查 | 每个需求动作结果符合产品语义；记录只变更一次、状态与关联一致、无意外副作用 |
| 路由与可达性 | 从启动页点击到每个当前路由；枚举当前 `WorkbenchSection`；覆盖旧别名、页内 Tab、返回栈、快速连续切换 | 当前用户入口均可达且落在正确页面/子页；兼容入口不空白、不误跳；Back 不困住用户 |
| 视觉一致性 | 对照 `ORGANIC_UI_SPEC.md`、`lib/core/theme/app_theme.dart` 和 `design_preview/assets/tokens.css`；逐页对比主题、字体、颜色、间距、圆角、图标和状态表达 | 使用当前语义令牌；无历史规范误用/随意硬编码；层级与组件一致；错误、完成、选中等不只靠颜色表达；Golden 差异均可解释 |
| 布局与响应式 | Golden/UI 矩阵 + 原生窗口/设备检查；视口覆盖 360×800、375×812、412×915、断点两侧、768、1024、1200、1440、1536×864，以及 812×375/915×412 横屏 | 非预期横向溢出、重叠、遮挡为 0；可滚动内容可操作；导航/固定栏不盖住主操作；旋转/改尺寸后状态不丢 |
| 文本与本地化 | 中文长标题/长标签/长 Markdown、空/特殊字符、英文/数字/emoji 混排；默认及 1.3×/1.5×/2×字号 | 关键文本不被裁切或遮住；控件不因内容改变而跳动；字形覆盖完整；日期/数字格式符合界面语义 |
| 交互反馈 | 对每个按钮、图标、手势、拖拽、菜单、表单执行鼠标/键盘/触屏；测慢操作、重复点击、禁用态 | 关键操作有可发现入口和即时反馈；I/O 约 300ms 内出现加载/禁用状态；完成/失败反馈清楚；无仅靠 Hover 的关键功能 |
| 可用性与无障碍 | 键盘 Tab/Shift+Tab/Enter/Escape/方向键、焦点顺序、屏幕阅读语义、对比度、触控尺寸、系统 Back、减少动效 | 焦点可见且顺序合理；控件名称/状态/错误可读；正文对比度至少 4.5:1、大字/重要图形至少 3:1；Android 触控目标至少 48dp；减少动效下不崩溃、不丢反馈 |
| 表单与校验 | 每类编辑器输入空值、空白字符、极长值、边界日期/数字、非法 URL、重复名称、切换 Tab 后返回、保存中取消 | 错误贴近字段且可理解；非法内容不落库；错误后输入保留；保存成功/失败状态可辨；连续提交不生成重复记录 |
| 状态与生命周期 | 用故障注入/可控时钟模拟数据库、文件、网络、权限失败；切页、退后台、重进、dispose；并发保存/计时边界 | 无未处理异常、陈旧 UI、重复监听或后台 Timer 泄漏；失败不造成半更新；重试可恢复；状态通知与持久化一致 |
| 异常与恢复 | 对每个 I/O 和平台调用模拟无权限、文件损坏/丢失、空间不足、超时、离线、无配置、原生桥缺失 | 用户获得准确、非误导的原因及恢复办法；保留可恢复输入；失败不破坏既有数据；不支持功能明确降级 |
| 数据一致性 | SQLite 临时库往返、关闭重开、迁移前后对比；任务/项目/附件/软删除/同步状态交叉验证 | 事务成功则整体提交、失败则不留半状态；关系无孤儿；删除/恢复语义一致；迁移数据可追溯且无静默丢失 |
| 安全与隐私 | 检查密钥/配置/日志/文件路径；错误密码、畸形/超大嵌套备份、恶意导入值、RLS、权限最小化；自律只在隔离环境验证 | 无服务端密钥或私密内容泄露；错误密码和非法文件不修改数据；恢复前可确认；云端按用户隔离；hosts/结束进程有明确授权和回滚 |
| 性能与稳定性 | 大量记录、长列表/树、搜索快速输入、页面快速切换、长专注计时、同步批次；观察卡顿、重绘、内存和 I/O | 无明显卡死/ANR/窗口无响应；搜索/切页响应稳定；列表增长不导致明显线性卡顿；资源在离页后释放；基准值及设备写入报告 |
| 自动化有效性 | 检查测试确实挂载真实路径、断言状态变化和持久化；核对 fixture 不掩盖数据库/平台行为 | 测试有明确前置、操作、结果断言；不得只断言控件存在；不跳过关键异常；Golden 只在确认设计变化后由审查者审批更新 |

对比度、触控尺寸和动效时长以当前产品设计规范与平台准则共同判定；若仓库旧文档与当前代码/规范矛盾，先记录为规范漂移并确认权威源，禁止任选一个历史数值作为通过依据。

## 5. 边界与故障场景矩阵

每个页面至少组合以下数据状态；与页面无关的场景标为 N/A 并说明理由，而不是默认跳过：

| 维度 | 最低场景集 |
| --- | --- |
| 数据量/关系 | 空库、单条、典型多条、长列表/长树、最大合法值、重复/缺失关联、软删除父项、孤儿附件 |
| 时间 | 04:00 逻辑日边界、跨午夜规则、周/月/年切换、月末 28/29/30/31 日、闰年、时区/夏令时、未来/历史日期 |
| 输入 | 空、空白、短/长、Unicode/emoji、换行/Markdown、特殊符号、非法数字/日期/URL、复制粘贴 |
| 操作时序 | 连点、双击、快速切页、操作中返回/关闭、并发保存、后台/前台切换、应用被终止后重进 |
| 依赖故障 | SQLite 写入失败/磁盘满、附件丢失/无权限、网络断开/超时、云凭据未配置、通知拒绝、MethodChannel 不可用 |
| UI 环境 | 亮/暗主题、系统字号至 200%、减少动效、键盘/IME 展开、横竖屏、最小窗口/低高度、屏幕阅读器/键盘焦点 |

## 6. 执行顺序与证据

1. **建立基线**：记录分支、提交、`git status --short`、Flutter/Dart 版本、连接设备、环境变量和本机权限；仅使用隔离数据目录。
2. **构建覆盖清单**：以 `WorkbenchSection`、`_buildPage`、页面/组件目录、设置项和控件回调为源生成页面×入口×状态清单；旧报告只作为线索，不作为现状事实。
3. **静态和单元检查**：运行 `dart format --output=none --set-exit-if-changed lib test`、`flutter analyze`、服务/模型/数据库/迁移/安全专项测试；审查依赖和异常处理。
4. **Widget 与组件流程**：逐个运行空态/有数据/错误 fixture；验证表单、菜单、弹层、焦点、状态更新、保存失败与 dispose。
5. **全量自动化与视觉矩阵**：运行 `flutter test --reporter compact`、Golden、UI 覆盖测试；覆盖断点、主题、字号、减少动效和状态矩阵。保留失败日志、截图和 diff；不得自动更新基线。
6. **平台 E2E**：按 `E2E-01`～`E2E-15` 在 Windows 和 Android 分别执行；使用项目构建脚本，记录真机型号/OS/分辨率/权限/电源状态。只读或无法安全模拟的危险系统行为标记 `BLOCKED` 并说明替代证据。
7. **复现与闭环**：每个问题建立独立 ID，最小化复现；修复后先跑针对用例，再跑关联回归和全量测试；同设备/同路径复验，记录修复提交或 diff、结果及残余风险。
8. **汇总**：输出覆盖率（已执行/计划项）、通过/失败/阻塞数、未覆盖项、缺陷清单、截图/日志位置、修复前后验证；未验证项不得写成“全流程通过”。

建议命令（实际设备构建按项目脚本及本机配置执行）：

```powershell
git status --short
flutter --version
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test --reporter compact
flutter test test/ui_audit_screenshot_test.dart
flutter test test/ui_coverage_regression_test.dart
flutter test test/visual_golden_test.dart
```

现有 `test/ui_audit_screenshot_test.dart`、`test/ui_coverage_regression_test.dart` 和 `test/visual_golden_test.dart` 可作为自动化底座；必须在审查时确认它们覆盖当前实际导航/页面与真实行为，不能把截图生成成功等同于交互、原生平台或可访问性已通过。

## 7. 缺陷记录格式

每条缺陷单独记录，至少包含下列字段；影响或根因尚未确认时写“待确认”，不猜测：

```markdown
### BUG-<序号>：<简短、可检索的问题标题>

- 模块/页面：
- 平台与版本：Windows / Android（设备型号、OS、构建号）
- 严重程度：P0 / P1 / P2 / P3
- 影响范围：受影响页面、用户、数据或依赖服务
- 前置条件/测试数据：
- 复现步骤：
  1. <第一步>
  2. <第二步>
  3. <第三步>
- 实际结果：
- 期望结果：
- 复现率：每 N 次复现 M 次
- 证据：截图/录屏/日志/堆栈/数据库前后差异（路径或附件 ID）
- 初步成因：待确认 / <有证据支持的原因>
- 临时规避：无 / <步骤>
- 修复验证：目标测试、回归范围、结果、日期/构建
- 状态：待复现 / 已确认 / 修复中 / 待验证 / 已关闭 / 阻塞
```

### 严重程度

| 级别 | 判定标准 | 处置 |
| --- | --- | --- |
| P0 阻断/严重 | 数据丢失或损坏、安全/隐私泄露、无法启动、核心主流程不可用、不可逆副作用 | 立即停止相关破坏性测试；优先修复并验证，未关闭不得宣称可发布 |
| P1 高 | 主要流程或关键平台功能失败；无可接受替代路径；大量用户受影响 | 当前审查周期必须修复或明确阻塞发布 |
| P2 中 | 局部功能/边界场景错误，有有限规避方式；明显视觉或交互缺陷 | 登记影响与规避，纳入修复和回归计划 |
| P3 低 | 文案、对齐、轻微视觉一致性或低风险易用性问题，不改变数据/核心流程 | 记录并排期；不与高风险缺陷混淆 |

优先级按“影响程度 × 发生频率 × 可恢复性 × 数据/安全风险”综合判断；同一根因影响多个模块时建立一个根因问题并列出全部受影响路径。

## 8. 完成判定

- 每个当前导航页、组合子页、兼容入口、共享交互组件、关键设置项和 E2E 路径均有状态明确的检查记录。
- 所有检查状态为 `PASS`、`FAIL` 或带具体原因的 `BLOCKED`；没有“未测但默认通过”。
- P0/P1 缺陷已修复并经回归确认，或明确列为阻塞项；无未解释的 Golden 差异和测试失败。
- 主要用户流程在 Windows 与 Android 的适用路径均完成；平台不适用/无法安全测试项注明范围和替代证据。
- 视觉、布局、交互、异常恢复和数据持久化均有截图/日志/测试结果支撑；自动化证据与原生设备证据分栏。
- 最终报告列出实际执行命令、真实测试数量、设备、失败和异常、修复前后结果、尚存风险及未覆盖范围。

## 9. 文档与规范来源

- 页面/导航现状以 `lib/ui/workbench_shell.dart` 与当前 `lib/ui/pages/`、`lib/ui/widgets/` 为准。

- 审查完成后，将实际结果更新到 `docs/qa/TEST_MATRIX.md`、`docs/qa/PROJECT_MAP.md` 和本轮报告；本方案只规定审查口径，不替代结果记录。
